----------------------------------------------------------------------
STORAGE / DURABILITY
----------------------------------------------------------------------
{{- if or .Values.postgres.enabled .Values.redis.enabled .Values.clickhouse.enabled }}
This release runs one or more BUNDLED datastores. How long their data
survives depends entirely on the storage scenario you chose:

{{- if and .Values.postgres.enabled (not .Values.postgres.persistence.enabled) }}
  postgres   : EPHEMERAL (emptyDir) -> tenants, API keys, models, config
               are LOST on any pod restart, reschedule, node drain, or reboot.
{{- else if .Values.postgres.enabled }}
  postgres   : persistent (PVC{{ with .Values.postgres.persistence.storageClass }}, storageClass={{ . }}{{ end }}) -> survives pod restarts.
{{- end }}
{{- if and .Values.clickhouse.enabled (not .Values.clickhouse.persistence.enabled) }}
  clickhouse : EPHEMERAL (emptyDir) -> usage history LOST on restart.
{{- else if .Values.clickhouse.enabled }}
  clickhouse : persistent (PVC{{ with .Values.clickhouse.persistence.storageClass }}, storageClass={{ . }}{{ end }}) -> survives pod restarts.
{{- end }}
{{- if and .Values.redis.enabled (not .Values.redis.persistence.enabled) }}
  redis      : EPHEMERAL (emptyDir) -> cache LOST on restart (rebuilt from Postgres).
{{- else if .Values.redis.enabled }}
  redis      : persistent (PVC{{ with .Values.redis.persistence.storageClass }}, storageClass={{ . }}{{ end }}).
{{- end }}

  NOTE: even a PVC-backed bundled datastore is a single plain Deployment with
  no backups or HA. A PVC also does not protect you from permanent loss of the
  node it lives on (e.g. node-local provisioners like local-path). For anything
  you care about long-term, use the EXTERNAL storage scenario (managed/operator
  Postgres + HA Redis + ClickHouse): examples/values-external.yaml.

  If a datastore pod is stuck Pending after install, its PVC almost certainly
  did not bind. Check it:

    kubectl get pvc -n {{ .Release.Namespace }}

  A PVC stuck "Pending" with "no persistent volumes available ... and no storage
  class is set" means the cluster has NO DEFAULT StorageClass and you left
  persistence.storageClass empty. Fix either by pinning a class:

    --set postgres.persistence.storageClass=<name> (likewise redis/clickhouse)

  or by marking one StorageClass default:

    kubectl patch storageclass <name> -p \
      '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"true"}}}'
{{- else }}
This release uses EXTERNAL datastores. obleth runs only its stateless
workloads; durability/backups/HA are managed by your external Postgres,
Redis, and ClickHouse.
{{- end }}
